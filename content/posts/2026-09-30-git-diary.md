2016 年冬天，我在一个私有仓库里提交了第一行日记。那时候的理由很实际：Markdown 比任何日记 App 都活得久，而 Git 我每天都在用。

没想到一写就是十年。

## 为什么是 Git

日记软件换过很多个。有的倒闭了，有的被收购后开始弹会员广告，有的把数据锁在只有它自己能读的格式里。每一次迁移都像搬家，总有些东西在过程中弄丢。

Git 的好处是它不关心内容。一堆纯文本，加上时间戳，仅此而已。十年后我用任何编辑器都能打开 2016 年的那个文件，不需要装任何软件。

坏处也有：它不会提醒你写，不会给你配图，也不会在年底生成一份漂亮的回顾。这些得自己想办法。

## 提交信息就是目录

我的提交信息有一个很简单的约定：

| 前缀 | 用途 | 例子 |
| :--- | :--- | :--- |
| `记:` | 当天发生的事 | `记: 雨, 修好了阳台的灯` |
| `读:` | 摘抄和读后感 | `读: 冬牧场 第三章` |
| `想:` | 没来由的念头 | `想: 关于“定居”这件事` |
| `改:` | 修订旧日记 | `改: 补全 2019-03 的空档` |

这样一来，`git log` 本身就是一份索引：

```bash
git log --oneline --since="2026-01-01" --grep="^读:"
```

十年来，这条命令替我找回过很多以为已经忘掉的书和句子。

## 一个小脚本

每天写完，我会跑一个很短的脚本。它做的事只有三件：把当天的文件加进去、用日期做提交信息、推送到远端。

```bash
#!/usr/bin/env bash
set -euo pipefail

day=$(date +%F)
file="entries/${day}.md"

[ -f "$file" ] || printf '# %s\n\n' "$day" > "$file"
${EDITOR:-vim} "$file"

git add "$file"
git commit -m "记: ${day}" || exit 0
git push origin main
```

脚本本身没什么技术含量，重要的是它把“写日记”这件事的成本降到了两条命令。**能坚持下来的习惯，通常都不需要意志力，只需要足够短的路径。**

## 十年之后

前阵子我导出了一次全部记录，三十多万字。用 `git log --reverse` 从第一条开始翻，看到 2016 年的自己为一件现在完全想不起来的事焦虑了整整两周，忽然觉得有点好笑，也有点羡慕。

那时候的他不知道后来会发生什么，所以每一件小事都显得很大。

这大概就是记日记的意义：不是为了记住，是为了在很久以后，还能认出那个当时的自己。

> 时间不会自己留下痕迹，是记录让它有了形状。
